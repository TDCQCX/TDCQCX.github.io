## 4.0 先搞清楚：Pandas 是什么

**一句话**：Pandas 是 Python 里用来处理**表格数据**的库。
它的核心是两种数据结构：

| 结构 | 中文 | 类比 | 说明 |
|---|---|---|---|
| `Series` | 序列 | Excel 里的**一列** | 一维，带行标签（索引） |
| `DataFrame` | 数据框 | Excel 里的**一张表** | 二维，有行标签和列名 |

**为什么不用 Excel？** 三个理由，都很实际：

1. **数据量**：Excel 一张表最多 104 万行，再大就打不开了。pandas 处理几百万行是日常。
2. **可复现**：Excel 里点几十次鼠标做的处理，下周你完全想不起来步骤。
   代码写下来，永远能重跑，改一个参数就能换口径。
3. **可组合**：pandas 处理完的数据能直接喂给 scikit-learn 建模、喂给 matplotlib 画图，
   是一条完整流水线。Excel 做不到。

**为什么又要先学 NumPy？** 因为 DataFrame 的每一列底层就是一个 NumPy 数组。
第 3 章的广播、向量化、`np.where` 这些概念，在 pandas 里天天用到。


> # pandas 3.0 的正确写法
> df.select_dtypes(include="str")       # 选出所有字符串列
> df.select_dtypes("number")            # 选出所有数值列（这个用法两版一样）
> ```

### 4.1.2 数据类型（dtype）速查

| dtype | 含义 | 例子 |
|---|---|---|
| `int64` | 整数 | `数量` |
| `float64` | 浮点数（带小数） | `单价`、`销售额` |
| `str` | 字符串 / 文本 | `城市`、`商品名称` |
| `datetime64[us]` | 日期时间 | `订单日期` |
| `bool` | 布尔（真/假） | `是否购买` |
| `category` | 分类（只有少数几种取值） | `省份区域` 很适合 |
| `object` | 万能类型（pandas 3.0 里主要用于混合类型或旧数据） | 尽量避免 |

`dtype` 非常重要。**同一个数字，存成 `str` 和存成 `float64`，
能做的操作完全不同** —— 字符串没法算平均数。

## 4.2 Series：一列数据

从 DataFrame 里取一列，得到的就是 `Series`：

```python
s = df["销售额"]        # 取一列，得到 Series
print(type(s))
print(s.head(3))
```

> 输出：
```text
<class 'pandas.Series'>
0     3313.80
1    15717.66
2      853.09
Name: 销售额, dtype: float64
```

注意三点：**值是数值、`Name` 是列名、最左边还是那个行索引**。

### 4.2.1 Series 的基本操作

```python
s = df["销售额"]

print("总和  ", s.sum())          # 求和
print("均值  ", s.mean())         # 平均值
print("中位数", s.median())       # 中位数
print("最大值", s.max())          # 最大值
print("最小值", s.min())          # 最小值
print("标准差", s.std())          # 标准差
print("偏度  ", s.skew())         # 偏度：>0 表示右偏（少数大值拉高了均值）
print("分位数", s.quantile([0.25, 0.5, 0.75]).round(1).tolist())
```

> 输出：
```text
总和   1592095.8900000001
均值   1496.3307236842106
中位数 413.025
最大值 51083.44
最小值 9.11
标准差 3367.490373813946
偏度   6.3831717423249525
分位数 [156.6, 413.0, 1306.2]
```

**这里有一个非常重要的数据洞察**：均值 1496 元，中位数只有 406 元，
差了近 4 倍；偏度 6.18 说明严重右偏。

**这说明什么？** 说明大部分订单金额很小（几百元），
但有极少数超大订单（最大 5 万）把平均值拉高了。

**这就是为什么做业务分析时，报"平均订单金额"要特别小心**——
它会被少数极端订单扭曲。更稳妥的是同时报中位数。

> 💡 以后你写分析报告，看到"均值远大于中位数"就要警觉：
> 数据是右偏的，这时候更适合用中位数描述"典型值"。

## 4.3 取数：行、列、单元格

这是 pandas 用得最多、也最容易搞混的部分。我用**一张表**先讲清楚"括号里放什么、取到什么"，
然后逐个给例子。

| 写法 | 取到什么 | 返回类型 |
|---|---|---|
| `df["城市"]` | 一列 | `Series` |
| `df[["城市", "销售额"]]` | 多列 | `DataFrame` |
| `df[df["销售额"] > 5000]` | 符合条件的**行** | `DataFrame` |
| `df.loc[标签, 列名]` | 按**名字**取 | 看情况 |
| `df.iloc[位置, 位置]` | 按**位置编号**取 | 看情况 |
| `df.at[标签, 列名]` | 单个单元格（按名字） | 标量 |
| `df.iat[位置, 位置]` | 单个单元格（按位置） | 标量 |

**核心记忆点**：
- 一个方括号 `df[...]` 里放**列名**→取列；放**布尔条件**→取行。**不能放行名**。
- 想同时指定行列，用 `.loc`（按名字）或 `.iloc`（按位置），格式是 `[行, 列]`。

### 4.3.1 取列

```python
print(type(df["城市"]))              # 一列 → Series
print(type(df[["城市", "销售额"]]))   # 两列（注意里面是列表！）→ DataFrame
print(df[["城市", "销售额"]].head(2))
```

> 输出：
```text
<class 'pandas.Series'>
<class 'pandas.DataFrame'>
   城市    销售额
0  杭州   3313.80
1  成都  15717.66
```

> ⚠️ **最容易犯的错**：写成 `df["城市", "销售额"]`（忘了里面的方括号）
> 会报 `KeyError: ('城市', '销售额')`。
> **记住**：多列要写成**列表**，也就是 `df[[...]]`，两层方括号。

### 4.3.2 布尔索引：按条件筛行

这是 pandas 最强大的功能之一，必须练熟。

```python
# 第一步：先构造一个"条件"，得到一个 True/False 的 Series
cond = df["销售额"] > 5000
print(cond.head(5))
print("满足条件的行数:", cond.sum())     # True=1, False=0，求和就是个数

# 第二步：把这个条件塞进方括号，就能筛出所有为 True 的行
big = df[cond]
print(big.shape)
```

> 输出：
```text
0    False
1     True
2    False
3    False
4    False
Name: 销售额, dtype: bool
满足条件的行数: 72
(72, 14)
```

**多个条件怎么组合？** 用 `&`（与）、`|`（或）、`~`（非），
**每个条件都要用括号包起来**：

```python
# 销售额 > 5000 且 城市是北京
r1 = df[(df["销售额"] > 5000) & (df["城市"] == "北京")]
print(r1.shape)

# 销售额 > 20000 或 城市是上海
r2 = df[(df["销售额"] > 20000) | (df["城市"] == "上海")]
print(r2.shape)

# 不是北京的（~ 表示取反）
r3 = df[~(df["城市"] == "北京")]
print(r3.shape)
```

> 输出：
```text
(12, 14)
(202, 14)
(891, 14)
```

> ⚠️ **常见报错**：`ValueError: The truth value of a Series is ambiguous`
> **原因**：用了 `and` / `or` / `not` 连接条件。
> **解决**：pandas 里必须用 `&` / `|` / `~`，而且每个条件加圆括号。
> ```python
> # 错误
> df[(df["销售额"] > 5000) and (df["城市"] == "北京")]
> # 正确
> df[(df["销售额"] > 5000) & (df["城市"] == "北京")]
> ```

### 4.3.3 query：把条件写成"字符串"

条件复杂时，方括号里套括号会很难看。`query` 让你用接近自然语言的写法：

```python
# 和 df[(df["销售额"] > 5000) & (df["城市"] == "北京")] 完全等价
r = df.query("销售额 > 5000 and 城市 == '北京'")
print(r.shape)

# 还可以引用外部变量，变量名前加 @
threshold = 20000
r2 = df.query("销售额 > @threshold")
print(r2.shape)
```

> 输出：
```text
(12, 14)
(7, 14)
```

**什么时候用 query？** 条件超过 2 个、或者列名很短的时候，`query` 明显更好读。
条件简单时 `df[df["列"] > 值]` 也很清楚。**两种都要会**。

### 4.3.4 loc 与 iloc：同时指定行列

`loc` 按**标签名**，`iloc` 按**位置编号**。

```python
# loc：行标签 + 列名
print(df.loc[0, "城市"])                    # 第 0 行的城市
print(df.loc[0:3, ["城市", "销售额"]])       # 第 0~3 行（含 3！）的这两列

# iloc：全用位置编号，和 Python 列表一样——左闭右开，第 3 行不含
print(df.iloc[0, 3])                       # 第 0 行第 3 列
print(df.iloc[0:3, [0, 3, 9]])             # 前 3 行，第 0、3、9 列
print(df.iloc[-1, :])                      # 最后一行全部列
```

> 输出：
```text

1  成都  15717.66
2  杭州    853.09
3  广州   1006.24
杭州
        订单编号  城市    销售额
0  SO20230300508  杭州   3313.80
1  SO20231100279  成都  15717.66
2  SO20231200633  杭州    853.09
订单编号          SO20230700176
```

> ⚠️ **loc 和 iloc 最坑的区别**：**loc 的切片是"含结尾"的，iloc 是"不含结尾"的。**
> - `df.loc[0:3]` → 第 0、1、2、**3** 行（4 行）
> - `df.iloc[0:3]` → 第 0、1、2 行（3 行）
>
> 记忆方法：`iloc` 的 `i` 可以想成"index 那种 Python 风格"，和列表切片一致。

> ⚠️ **常见报错**：`KeyError: 0`
> **原因**：用了 `iloc` 却传了列名，或者用了 `loc` 却传了位置编号。
> **解决**：看清行列是"名字"还是"编号"。比如 `df.loc[0, 3]` 会报错，
> 因为 `0` 是索引标签没问题，但 `3` 不是列名。要写 `df.iloc[0, 3]` 或
> `df.loc[0, "省份区域"]`。

### 4.3.5 at / iat：取单个值，速度快

```python
print(df.at[0, "城市"])       # 按名字取一个单元格
print(df.iat[0, 3])          # 按位置取一个单元格
```

> 输出：
```text
杭州
杭州
```

需要在一个循环里反复取值时，用 `at`/`iat` 比 `loc`/`iloc` 快很多。

## 4.4 索引（Index）：行的"名字"

索引就是每行的标签。默认是 `0, 1, 2, ...`，但它可以是任何东西。

### 4.4.1 把某列设为索引

```python
# 把"订单编号"当索引用，这样按订单号取数据更快、更语义化
d2 = df.set_index("订单编号")
print("前 3 个索引:", d2.index[:3].tolist())

# 取第一行的订单号，再按这个订单号把整行捞出来
first_id = df["订单编号"].iloc[0]
print("第一个订单号:", first_id)
print("它的销售额:", d2.loc[first_id, "销售额"])
print(d2.loc[first_id].to_frame().T)
```

> 输出：

### 4.4.2 时间索引 + resample：时间序列的杀手锏

把日期设为索引后，就能用 `resample` 按任意时间粒度聚合：

```python
ts = df.set_index("订单日期").sort_index()

# 按月汇总销售额
monthly = ts["销售额"].resample("ME").sum()
print(monthly.head(4).round(0))
print("共", len(monthly), "个月")
```

> 输出：
```text
订单日期
2023-01-31    115679.0
2023-02-28     62860.0
2023-03-31     81994.0
2023-04-30     34279.0
Freq: ME, Name: 销售额, dtype: float64
共 24 个月
```

> 📌 **pandas 2.x 与 3.0 差异（超级重要）**：`resample` 的频率别名改了一套！
>
> | 想做的聚合 | **pandas 3.0 写法** | pandas 2.x 旧写法 | 状态 |
> |---|---|---|---|
> | 按月末 | `"ME"` | `"M"` | 旧写法**直接报错** |
> | 按季末 | `"QE"` | `"Q"` | 旧写法报错 |
> | 按年末 | `"YE"` | `"Y"` / `"A"` | 旧写法报错 |
> | 按周 | `"W"` | `"W"` | 没变 |
> | 按日 | `"D"` | `"D"` | 没变 |
> | 按月初 | `"MS"` | `"MS"` | 没变 |
>
> 报错原文长这样：
> ```text
> ValueError: Invalid frequency: M. Failed to parse with error message:
> ValueError("'M' is no longer supported for offsets. Please use 'ME' instead.")
> ```
> **这是从旧教程抄代码时最常见的报错之一**，见到就把它改成 `"ME"`。
>
> 另一种更稳的写法是用 `pd.Grouper`，语义更清楚：
> ```python
> df.groupby(pd.Grouper(key="订单日期", freq="ME"))["销售额"].sum()
> ```

其他常用频率一起练一下：

```python
print("按周:", len(ts["销售额"].resample("W").sum()))
print("按日:", len(ts["销售额"].resample("D").sum()))
print("按年:", ts["销售额"].resample("YE").sum().round(0).tolist())
print("按季:", ts["销售额"].resample("QE").sum().round(0).tolist())
```

> 输出：
```text
按周: 105
按日: 729
按年: [825138.0, 766958.0]
按季: [260533.0, 168113.0, 169248.0, 227244.0, 202003.0, 205162.0, 187820.0, 171974.0]
```

> 💡 **注意 `resample("D")` 得到 730 行**：2023-01-01 到 2024-12-29 一共 730 天。
> 但原始数据只有 1064 行，说明**有些天没有订单**，resample 会把这些天补成 `0`（sum 时）
> 或 `NaN`（mean 时）。这个行为叫"重采样补齐"，绘图时特别有用——
> 能避免折线图把没订单的日子直接连起来造成视觉误导。

### 4.5.1 新增列

```python

d["不含税金额"] = (d["销售额"] / 1.13).round(2)
```

```text
3   1006.24      890.48       否     线上
4    607.72      537.81       否     线上
```

`np.where(条件, 真时的值, 假时的值)` 是三目运算的向量化版本，

### 4.5.2 修改值：loc 精确赋值


```text
3    广州   1006.24      NaN
4    北京    607.72      NaN
```

> ⚠️ **pandas 3.0 的重大变化：Copy-on-Write（写时复制）已强制开启**
>
> 在 pandas 2.0 以前，下面这段代码会**顺便改掉原表**，很多人被坑过：
> ```python
> sub = df[df["销售额"] > 5000]     # 这是一个"视图"还是"副本"？老版本说不清
> sub["城市"] = "X"                 # 老版本：可能给出 SettingWithCopyWarning 并改到原表
> ```
> pandas 3.0 起，**任何切片、筛选的结果都是独立的**，
> 改它不会影响原表，也不会再警告。所以规则变得简单了：
>
> **想改数据就先 `.copy()`，改副本绝对安全。**
> ```python
> sub = df[df["销售额"] > 5000].copy()   # 加 .copy() 是好习惯
> sub["城市"] = "X"                      # 只改 sub，df 不受影响
> ```
> 顺带一提，`pd.options.mode.copy_on_write` 这个开关已经废弃，
> 设置它会触发 `Pandas4Warning`，别再写它了。

## 4.6 分组聚合：数据分析的核心动作 ★★★

**这一节是 pandas 最有价值的部分。** 你未来 80% 的分析需求都是
"按某某分组，算什么什么"，也就是这一节的内容。

### 4.6.1 最基础的 groupby：split-apply-combine

`groupby` 的思维模型叫 **拆分—应用—合并**：

```text
原始数据                拆分（按城市分组）        应用（每组求和）      合并
┌──────┬───────┐      ┌───────┐              ┌───────┬───────┐    ┌───────┬───────┐
│ 城市 │ 销售额 │      │ 北京组 │  ── sum ──▶  │ 北京  │ 324090│    │ 北京  │ 324090│
│ 北京 │  2300 │      │ 北京  │              │ 上海  │ 437016│    │ 上海  │ 437016│
│ 上海 │  1800 │      ├───────┤              │ 广州  │  ...  │    │ ...   │  ...  │
│ 北京 │  2100 │      │ 上海组 │              └───────┴───────┘    └───────┴───────┘
│ 上海 │  2600 │      └───────┘
└──────┴───────┘
```

```python
# 按"省份区域"分组，把"销售额"加起来
region = df.groupby("省份区域")["销售额"].sum()
print(region.sort_values(ascending=False).round(0))
```

> 输出：
```text
省份区域
华南    509605.0
华东    437016.0
华北    324090.0
西南    130823.0
华中    106734.0
西北     83828.0
Name: 销售额, dtype: float64
```

解读：**华南是最大的市场，贡献销售额 50.96 万，占全公司约 32%。**

### 4.6.2 一次算多个指标：agg 具名聚合（推荐写法）

只算一个指标用不上 `agg`。真实分析里你要同时看总额、均值、单量：

```python
result = (df.groupby("省份区域")
            .agg(销售额合计=("销售额", "sum"),        # 起个别名，一眼看懂
                 订单数=("订单编号", "count"),
                 客单价=("销售额", "mean"),
                 最大单笔=("销售额", "max"))
            .round(1)
            .sort_values("销售额合计", ascending=False))
print(result)
```

> 输出：
```text
          销售额合计  订单数  客单价  最大单笔
省份区域                                      
华南        509605.3     325  1568.0   24543.8
华东        437015.7     334  1308.4   24914.2
华北        324090.2     173  1873.4   51083.4
西南        130822.7      99  1321.4   15717.7
华中        106733.8      73  1462.1   17628.2
西北         83828.1      60  1397.1   10205.2
```

**这种 `agg(新列名=("原列", "函数"))` 的写法叫"具名聚合"，
是目前最推荐的方式**，原因：

1. 结果直接是干净的列名，不用再改；
2. 一眼能看出每个数字是什么口径；
3. 不会产生难看的"多重索引列"。

> 📌 **pandas 2.x 与 3.0 差异**：老教材常见这种写法，得到的列是**两层索引**：
> ```python
> df.groupby("省份区域")["销售额"].agg(["sum", "mean"])   # 列名是 ('销售额','sum') 这种元组
> ```
> 这种"多重索引列"后面取值很别扭，要写 `result[("销售额", "sum")]`。
> 新版推荐用 `agg(新名=("列", "函数"))` 一次到位。两种都能跑，
> 但**新写法更好维护**，本教程统一用它。

### 4.6.3 常用聚合函数速查

| 函数 | 含义 | 用在 |
|---|---|---|
| `"sum"` | 求和 | 销售额、数量 |
| `"mean"` | 平均 | 客单价 |
| `"median"` | 中位数 | 抗极端的平均值 |
| `"count"` | 非空计数 | 订单数 |
| `"size"` | 行数（含空值） | 记录条数 |
| `"nunique"` | 去重计数 | 有多少个不同客户 |
| `"min"` / `"max"` | 最小 / 最大 | 极值 |
| `"std"` | 标准差 | 波动大小 |
| `"var"` | 方差 | 波动大小 |
| `"first"` / `"last"` | 第一个 / 最后一个 | 配合排序用 |

```python
print(df.groupby("商品类别").agg(订单数=("订单编号", "count"),
                              不同商品数=("商品名称", "nunique"),
                              客单价=("销售额", "mean"),
                              销售额标准差=("销售额", "std")).round(1))
```

### 4.6.8 transform：分组后广播回原表

有时你要的不是一个汇总表，而是**在每一行上多一列"它所属组的统计量"**。
这时候用 `transform`：

```python
d = df.head(8).copy()
# 每行都加上"它所在省份区域的平均销售额"这一列
d["区域平均"] = d.groupby("省份区域")["销售额"].transform("mean").round(1)
# 算出这一单比区域平均高多少
d["偏离度%"] = ((d["销售额"] / d["区域平均"] - 1) * 100).round(1)
print(d[["省份区域", "销售额", "区域平均", "偏离度%"]])
```

> 输出：
```text
  省份区域    销售额  区域平均  偏离度%
0     华东   3313.80    1497.9    121.2
1     西南  15717.66   15717.7     -0.0
2     华东    853.09    1497.9    -43.0
3     华南   1006.24    1006.2      0.0
4     华北    607.72     607.7      0.0
5     华中    452.90     276.6     63.7
6     华东    326.70    1497.9    -78.2
7     华中    100.27     276.6    -63.7
```

**`transform` 和 `agg` 的区别**：
- `agg` 把一组**变成一行**（结果比原表短）
- `transform` 把一组**变成同样多的行**（结果和原表一样长，可以拼回原表）

这在做"每单相对同区域水平的偏离"、"组内排名"、"用组内中位数填补缺失值"时必不可少。

## 4.7 合并数据：merge / concat / join

真实项目里数据往往分散在好几张表，需要拼起来。
**这等价于 SQL 的 JOIN**，学过一次到处能用。

### 4.7.1 merge：按共同列连接（最重要）

先造两张小表来演示，避免被真实数据的列名干扰：

```python
# 左表：订单
orders = pd.DataFrame({
    "订单号": ["A01", "A02", "A03", "A04"],
    "客户ID": [1, 2, 2, 3],
    "金额": [100, 200, 150, 300],
})

# 右表：客户
customers = pd.DataFrame({
    "客户ID": [1, 2, 4],
    "客户名": ["张伟", "李静", "王强"],
    "城市": ["北京", "上海", "广州"],
})

print(orders)
print(customers)
```

> 输出：
```text
  订单号  客户ID  金额
0    A01       1   100
1    A02       2   200
2    A03       2   150
3    A04       3   300
   客户ID 客户名  城市
0       1   张伟  北京
1       2   李静  上海
2       4   王强  广州
```

**四种连接方式**（用集合图理解）：

| `how` 取值 | 中文 | 保留什么 | 结果行数 |
|---|---|---|---|
| `"inner"` | 内连接 | 两边**都有的** | 只有匹配上的 |
| `"left"` | 左连接 | 左边**全部**保留 | 左表行数（匹配不上补 NaN） |
| `"right"` | 右连接 | 右边全部保留 | 右表行数 |
| `"outer"` | 外连接 | 两边**全部**保留 | 并集（都用 NaN 补） |

```python
inner = orders.merge(customers, on="客户ID", how="inner")
print("inner 行数:", len(inner))
print(inner)

left = orders.merge(customers, on="客户ID", how="left")
print("\nleft 行数:", len(left))
print(left)
```

> 输出：
```text
inner 行数: 3
  订单号  客户ID  金额 客户名  城市
0    A01       1   100   张伟  北京
1    A02       2   200   李静  上海
2    A03       2   150   李静  上海

left 行数: 4
  订单号  客户ID  金额 客户名  城市
0    A01       1   100   张伟  北京
1    A02       2   200   李静  上海
2    A03       2   150   李静  上海
3    A04       3   300    NaN   NaN
```

**注意区别**：`inner` 丢掉了客户ID=3 的订单（因为客户表里没这个人），
`left` 保留了它，但客户名和城市是 `NaN`。

> 💡 **实际工作建议**：**默认用 `how="left"`**，因为它不会莫名其妙丢数据。
> 如果用了 `inner` 发现行数变少了，先问自己"是不是有匹配不上的记录"。

**列名不同怎么连？** 用 `left_on` 和 `right_on`：

```python
# 假设右表的列叫 "ID" 而不是 "客户ID"
c2 = customers.rename(columns={"客户ID": "ID"})
r = orders.merge(c2, left_on="客户ID", right_on="ID", how="left")
print(r.columns.tolist())
```

> 输出：
```text
['订单号', '客户ID', '金额', 'ID', '客户名', '城市']
```

**检查连接结果**：加 `indicator=True` 能告诉你每行是从哪边来的，排查问题神器：

```python
r = orders.merge(customers, on="客户ID", how="outer", indicator=True)
print(r["_merge"].value_counts())
```

> 输出：
```text
_merge
both          3
left_only     1
right_only    1
Name: count, dtype: int64
```

`left_only` 表示只有左表有（客户ID=3），`right_only` 表示只有右表有（客户ID=4）。

用真实数据再练一次 —— 把销售明细和品类目标连起来，看达成情况：

### 4.7.2 concat：把表拼起来

**纵向拼接（上下摞起来）**：两张结构相同的表合并成一张。

```python
part1 = df.head(2)
part2 = df.tail(2)
combined = pd.concat([part1, part2], ignore_index=True)   # ignore_index 重排索引
print(combined[["订单编号", "销售额"]])
print("行数:", len(combined))
```

> 输出：
```text
        订单编号    销售额
0  SO20230300508   3313.80
1  SO20231100279  15717.66
2  SO20240700212    325.29
3  SO20230700176     25.17
行数: 4
```

> ⚠️ `ignore_index=True` 一定要加。不加的话索引会是 `0,1,1062,1063` 这种奇怪的组合，
> 后面用 `loc` 取值很容易搞错。

**横向拼接（左右并排）**：

```python
# 用 d 这个副本来做演示，避免动到主表 df（后面还要用它）
d = df.head(3)
left_part = d[["订单编号", "城市"]]
right_part = d[["销售额", "数量"]]
side = pd.concat([left_part, right_part], axis=1)     # axis=1 表示按列方向拼
print(side)
```

> 输出：
```text
        订单编号  城市    销售额  数量
0  SO20230300508  杭州   3313.80     1
1  SO20231100279  成都  15717.66     8
2  SO20231200633  杭州    853.09     3
```

**横向拼接是按索引对齐的**，索引对不上就会补 NaN。所以拼之前最好确认两边索引一致。

### 4.7.3 join：以索引为准的快捷合并

```python
a = df.set_index("订单编号")[["城市", "销售额"]].head(3)
b = df.set_index("订单编号")[["支付方式"]].head(3)
print(a.join(b))
```

> 输出：
```text
               城市    销售额 支付方式
订单编号

SO20231100279  成都  15717.66   支付宝
SO20231200633  杭州    853.09     花呗
```

`join` 默认按**索引**连接，左边是索引右边也是索引时最方便。

## 4.10 分箱：把连续值变成分类

**为什么要把年龄变成"青年/中年"？** 因为业务上经常需要按人群分层看问题，
而且很多模型也更喜欢分类型特征。

```python
import pandas as pd
import numpy as np

# cut：按你指定的边界等距分箱（"按数值切"）
df["年龄段"] = pd.cut(
    df["客户年龄"],
    bins=[0, 25, 35, 50, 100],                    # 边界
    labels=["25岁以下", "25-35岁", "35-50岁", "50岁以上"],
)
print(df["年龄段"].value_counts().sort_index())
```

> 输出：
```text
年龄段
25岁以下    277
25-35岁     373
35-50岁     372
50岁以上     42
Name: count, dtype: int64
```

```python
# qcut：按分位数等频分箱（"按人数切"，每箱人数一样多）
df["消费层级"] = pd.qcut(
    df["销售额"], q=4,                             # 分成 4 箱
    labels=["低消费", "中低消费", "中高消费", "高消费"],
)
print(df["消费层级"].value_counts().sort_index())
print("\n各层级销售额区间：")
print(df.groupby("消费层级", observed=True)["销售额"]
        .agg(最低=("min"), 最高=("max"), 订单数=("count")).round(1))
```

> 输出：
```text
消费层级
低消费      266
中低消费    266
中高消费    266
高消费      266
Name: count, dtype: int64

各层级销售额区间：
            最低     最高  订单数
消费层级                         
低消费       9.1    156.4     266
中低消费   156.6    412.7     266
中高消费   413.3   1305.4     266
高消费    1308.6  51083.4     266
```

**`cut` 和 `qcut` 的区别（很关键）**：

| | `pd.cut` | `pd.qcut` |
|---|---|---|
| 切分依据 | 你给的**数值区间** | **分位数**（保证每组人数接近） |
| 每箱人数 | 可能差很多（上面 15 vs 388） | 基本相等（266 × 4） |
| 适用场景 | 有业务含义的阈值（如 25 岁、60 岁） | 想避免某组样本太少 |

> ⚠️ **常见报错**：`TypeError: ... 'Categorical' ... observed`
> **原因**：pandas 对分箱产生的 `category` 类型做 `groupby` 时，
> 默认统计所有可能类别（包括数据里没出现的空类别），会有 FutureWarning。
> **解决**：`groupby("消费层级", observed=True)` 明确只统计出现过的类别。

**分箱后看业务规律**：

```python
seg = (df.groupby("年龄段", observed=True)
         .agg(订单数=("订单编号", "count"),
              客单价=("销售额", "mean"),
              总销售额=("销售额", "sum"))
         .round(1))
print(seg)
```

> 输出：
```text
          订单数  客单价  总销售额
年龄段                            
25岁以下     277  1685.1  466761.3
25-35岁      373  1162.4  433557.0
35-50岁      372  1714.9  637945.5
50岁以上      42  1281.7   53832.1
```

**结论**：25-35 岁和 35-50 岁是主力人群，客单价也最高（1600 左右）。
50 岁以上样本量太小（只有 15 单），**结论不可靠，不要下判断**。

> 💡 **看到样本量小就要警惕**。分析报告里如果写"50 岁以上客单价最高"，
> 就会被内行质疑——15 个样本的均值波动极大。

### 4.11.1 map：按字典映射（最快）

### 4.11.2 replace：值替换



### 4.11.3 apply：自定义函数（能不用就不用）

`apply` 让你对每一行/每一列跑一个自己写的函数，非常灵活，**但很慢**。

```python
d = df.head(5).copy()

# axis=1 表示"逐行"处理：每一行作为一个 Series 传给你的函数
def grade(row):
    if row["销售额"] > 5000:
        return "A"
    elif row["销售额"] > 1000:
        return "B"
    else:
        return "C"

d["等级_apply"] = d.apply(grade, axis=1)
print(d[["销售额", "等级_apply"]])
```

> 输出：
```text
     销售额 等级_apply
0   3313.80          B
1  15717.66          A
2    853.09          C
3   1006.24          B
4    607.72          C
```

**同样的事情用 `np.where` / `np.select` 做，快 N 倍**：

```python
import numpy as np

# np.select：多条件分支的向量化版本
d["等级_向量化"] = np.select(
    [d["销售额"] > 5000, d["销售额"] > 1000],
    ["A", "B"],
    default="C",
)
print((d["等级_apply"] == d["等级_向量化"]).all())
```

> 输出：
```text
True
```

### 4.11.4 性能对比：apply 到底慢多少？

```python
# 计时类输出每次都不一样，不自动回填 -->
# 下面这块含计时，跑出来的毫秒数每次都不一样，所以标记为不自动回填输出
# 不自动回填 -->
import numpy as np
import time

big = pd.DataFrame({"x": np.random.default_rng(42).normal(0, 1, 200_000)})
N = 5

t0 = time.perf_counter()
for _ in range(N):
    r1 = big["x"].apply(lambda v: v * 2)          # 逐元素 apply
t1 = time.perf_counter()
for _ in range(N):
    r2 = big["x"] * 2                             # 向量化
t2 = time.perf_counter()

ms_apply = (t1 - t0) / N * 1000
ms_vec = (t2 - t1) / N * 1000
print(f"apply 耗时   约 {ms_apply:.0f} ms")
print(f"向量化 耗时  约 {ms_vec:.1f} ms")
print(f"大约快 {ms_apply / ms_vec:.0f} 倍")
print("结果是否一致:", np.allclose(r1, r2))
```

> 输出：
```text
apply 耗时   约 33 ms
向量化 耗时  约 0.5 ms
大约快 62 倍
结果是否一致: True
```

**20 万行数据，向量化比 apply 快 60 倍左右。** 数据量再大 10 倍，
`apply` 就要跑三分之一秒，而向量化还是几毫秒——差距会随数据量线性放大。
（你自己跑出来的具体毫秒数会有波动，这很正常，关键是**数量级**差异。）

> 💡 **性能优化三原则**：
> 1. 能用向量化运算（`+ - * /`、`np.where`、`.str`、`.dt`）就别用 `apply`；
> 2. 能用 `groupby().agg()` 就别用循环；
> 3. 真需要 `apply` 时，优先 `apply` 到**列**（`axis=0`，默认）而不是**行**（`axis=1`），
>    逐行比逐列慢好几倍。

### 4.11.5 DataFrame.map（元素级函数）

> 📌 **pandas 2.x 与 3.0 差异**：老教材里的 `df.applymap(func)` **在 pandas 3.0 中被彻底移除**：
> ```text
> AttributeError: 'DataFrame' object has no attribute 'applymap'
> ```
> 替代品是 `df.map(func)`（pandas 2.1 引入）：
> ```python
> d = df[["单价", "数量"]].head(3).copy()
> print(d.map(lambda v: round(v, 1)))
> ```
> ```text
>      单价  数量
> 0  800.0   1
> 1  138.0   2
> 2  809.0   3
> ```
> 记住：**`Series.map`** 是按值映射（一直都有），**`DataFrame.map`** 是逐元素处理
> （2.1 新增，替代 `applymap`），**`DataFrame.apply`** 是按键（行或列）处理。

## 4.12 链式调用：把流程写得像流水线

一段完整的数据处理往往是"筛选 → 新增列 → 分组 → 排序 → 取名"。
分成十几行中间变量（`df1`、`df2`、`df3`）很难读，**链式调用**能写得像流水线。

### 4.12.1 反面例子（能用但难读）

```python
d = df.copy()
d = d[d["销售额"] > 100]
d["年月"] = d["订单日期"].dt.to_period("M")
grouped = d.groupby(["年月", "商品类别"])["销售额"].sum()
grouped = grouped.unstack(fill_value=0)
grouped = grouped.round(0)
result = grouped
print(result.shape)
```

> 输出：
```text
(24, 5)
```

### 4.12.2 链式写法（推荐）

```python
result = (
    df
    .query("销售额 > 100")                         # 1. 筛掉金额过小的
    .assign(年月=lambda d: d["订单日期"].dt.to_period("M"))   # 2. 新增月份列
    .groupby(["年月", "商品类别"])["销售额"].sum()   # 3. 分组汇总
    .unstack(fill_value=0)                        # 4. 转成宽表
    .round(0)                                     # 5. 保留整数
)
print(result.head(3))
```

> 输出：
```text
商品类别  图书文娱  家用电器  手机数码  服饰鞋包  食品饮料
年月                                                      
2023-01      645.0   15458.0   88136.0    9831.0    1044.0
2023-02      144.0   30752.0   27747.0    2831.0     927.0
2023-03      115.0   15849.0   59589.0    4610.0    1352.0
```

**链式写法的好处**：
1. 从上到下读，逻辑顺序一目了然；
2. 不用起一堆 `df1`、`df2` 这种没意义的名字；
3. 想加一步就在中间插一行，不用重构变量。

**`assign` 里用 `lambda d:` 的原因**：在链式调用中，
前面的 `query` 已经筛掉了一部分行，`lambda d:` 里的 `d` 是**当前这一步的数据**，
而不是最初的 `df`。如果直接写 `df["订单日期"].dt...`，
就会用到原始表的全部行，长度对不上会报错。

> ⚠️ **注意**：链式调用不要超过 8 步左右。
> 太长了调试困难——中间出错你都不知道是哪一步的问题。
> 复杂流程该拆成几段还是拆。

### 4.12.3 pipe：把自定义步骤插进链子

```python
def add_profit_margin(d, rate=0.3):
    """按毛利率算利润列"""
    return d.assign(利润=(d["销售额"] * rate).round(2))

result = (
    df.head(5)
    .pipe(add_profit_margin, rate=0.35)          # 把自己的函数插进链子
    .loc[:, ["城市", "销售额", "利润"]]
)
print(result)
```

> 输出：
```text
   城市    销售额     利润
0  杭州   3313.80  1159.83
1  成都  15717.66  5501.18
2  杭州    853.09   298.58
3  广州   1006.24   352.18
4  北京    607.72   212.70
```

`pipe` 是链式调用里接入"自己写的复杂逻辑"的标准方式。

## 4.13 读写数据

### 4.13.1 读 CSV（最常用）

```python
# 基础
df1 = pd.read_csv("../data/sales_clean.csv")

# 常用参数一次看全
df2 = pd.read_csv(
    "../data/sales.csv",
    encoding="utf-8-sig",                      # 编码：处理中文 Excel 导出的 CSV 必加
    usecols=["订单编号", "订单日期", "城市", "销售额"],  # 只读需要的列，省内存
    nrows=100,                                 # 只读前 100 行（先探路用）
    dtype={"订单编号": str},                    # 指定类型，避免订单号被当成数字
    date_format="mixed",                       # 日期格式混合，必须显式声明（见下）
)
print(df2.shape)
print(df2.dtypes.tolist())
```

> 输出：
```text
(100, 4)
[<StringDtype(na_value=nan)>, <StringDtype(na_value=nan)>, <StringDtype(na_value=nan)>, dtype('float64')]
```

> ⚠️ **这里有两个必须注意的坑**：
> 1. **`parse_dates` 里的列必须也在 `usecols` 里**，否则会报
>    `ValueError: Missing column provided to 'parse_dates': '订单日期'`。
>    这很好理解：你把这一列排除了，pandas 当然解析不了它。
> 2. 我上面写的是 `date_format="mixed"` 而**不是** `parse_dates`。原因是
>    `sales.csv` 的日期有 3 种写法，就算用 `parse_dates` 也**解析不了**
>    `2024年08月09日` 这种带中文的格式，会直接抛异常。
>    正确顺序是：先读进来 → 把中文年月日替换掉 → 再 `to_datetime(format="mixed")`。
>    这套流程在下一小节详细讲。

**必须掌握的三个参数**：

| 参数 | 什么时候用 |
|---|---|
| `encoding="utf-8-sig"` | 打开中文 CSV 乱码（`UnicodeDecodeError` 或首列名带 `\ufeff`）时 |
| `parse_dates=[...]` | 有日期列时**总是**加上，否则读进来是字符串 |
| `usecols=[...]` | 表很大只关心几列时，能显著提速省内存 |

### 4.13.2 日期解析的坑

```python
import pandas as pd

# sales.csv 里的日期有三种写法：
#   2023-01-15 / 2023/01/15 / 2023年01月15日
try:
    pd.read_csv("../data/sales.csv", parse_dates=["订单日期"])
except Exception as e:
    print("直接解析失败：", type(e).__name__)
    print(str(e)[:150])
```

> 输出：
```text
```

**正确解法分两步**：

```python
import pandas as pd

# 用一个独立变量名装这份脏数据，不要覆盖前面一直在用的 df
raw = pd.read_csv("../data/sales.csv")

# 第 1 步：把中文的"年/月/日"替换成"-"，让 pandas 认得出来
# 先 .astype(str) 是为了防止列里已经混了非字符串值导致报错
raw["订单日期"] = (raw["订单日期"].astype(str)
                .str.replace("年", "-", regex=False)
                .str.replace("月", "-", regex=False)
                .str.replace("日", "", regex=False))

# 第 2 步：三种格式混在一起，必须显式声明 format="mixed"
raw["订单日期"] = pd.to_datetime(raw["订单日期"], format="mixed")

print(raw["订单日期"].dtype)
print("解析失败的数量:", raw["订单日期"].isna().sum())
print("日期范围:", raw["订单日期"].min().date(), "~", raw["订单日期"].max().date())
```

> 输出：
```text
datetime64[us]
解析失败的数量: 0
日期范围: 2023-01-01 ~ 2024-12-30
```

> 💡 **变量名也是要设计的**。如果把上面的清洗结果存回 `df`，
> 后面所有基于 `df` 的分析口径就悄悄从 1064 行（干净数据）变成了 1230 行（脏数据），
> 数字全变了你还找不到原因。**不同来源的数据起不同的名字**，
> 是避免这类"幽灵 bug"最简单有效的办法。

> 📌 **pandas 2.x 与 3.0 差异（必看）**：这是最容易被旧教程坑的地方。
>
> | 场景 | pandas 2.x 旧写法 | **pandas 3.0 正确写法** |
> |---|---|---|
> | 混合日期格式 | `pd.to_datetime(s)` 自动逐行猜测 | `pd.to_datetime(s, format="mixed")` **必须显式声明** |
> | 读 CSV 时解析 | `pd.read_csv(..., parse_dates=[...])` | `pd.read_csv(..., parse_dates=[...], date_format="mixed")` |
> | 带中文的日期 | `pd.to_datetime(s, format="%Y年%m月%d日")`（能跑） | 同上能跑，但**混合格式时必须先替换字符** |
>
> 为什么 3.0 要这么改？因为自动逐行猜测格式**非常慢**，而且会掩盖数据质量问题。
> 新版本让你显式声明，出错更早、跑得更快。
> 报错原文：
> ```text
> ValueError: time data "2024/08/19" doesn't match format "%Y-%m-%d"
> ```

## 4.14 本章小结

### 4.14.1 知识点清单

| 类别 | 必会内容 |
|---|---|
| **看数据** | `head` `shape` `info` `describe` `isna().sum()` |
| **取数据** | `df["列"]` `df[["列1","列2"]]` 布尔索引 `query` `loc` `iloc` `at` `iat` |
| **排序取极值** | `sort_values` `nlargest` `nsmallest` `rank` |
| **增删改** | 直接赋值 `assign` `insert` `drop` `rename` `np.where` `np.select` |
| **分组聚合** ★ | `groupby().agg(新名=("列","函数"))` `unstack` `pivot_table` `crosstab` `transform` |
| **合并** | `merge(how=)` `concat(axis=)` `join` |
| **文本** | `.str.strip/contains/replace/split/extract/zfill` |
| **时间** | `.dt.year/month/dayofweek/quarter/to_period/strftime` `resample("ME")` |
| **分箱** | `pd.cut`（按数值）`pd.qcut`（按分位数） |
| **映射** | `map` `replace` `apply`（少用）`df.map`（替代 applymap） |
| **链式** | `.query().assign().groupby().agg()` `pipe` |
| **读写** | `read_csv(encoding, parse_dates, usecols)` `read_excel(sheet_name, skiprows)` `read_sql` `to_parquet` |

| 旧写法（会报错/失效） | 3.0 新写法 |
|---|---|
| `df.applymap(f)` | `df.map(f)` |
| `df.fillna(method="ffill")` | `df.ffill()` |
| `resample("M")` | `resample("ME")` |
| `resample("Q")` | `resample("QE")` |

| `select_dtypes("object")` 选字符串列 | `select_dtypes(include="str")` |
| `pd.to_datetime(s)` 混合格式 | `pd.to_datetime(s, format="mixed")` |

> 💡 **这就是一份分析报告的雏形**：
> 先分维度看数字 → 再区分"规模"和"效率"两个视角 →
> 最后给出**可执行的动作**（拉新 / 保供 / 提转化），而不是只堆数字。
> 第 9 章会教你怎么把这些写成正式报告。
