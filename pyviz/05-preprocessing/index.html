学习目标

学完本章你能做到：

  1. 拿到一份陌生的数据，几分钟内做出一份数据质量体检报告（哪列缺、缺多少、有没有重复、有没有离谱的值）；
  2. 判断缺失值到底该删、该填、还是该保留，并知道每种填法会把结论带偏多少；
  3. 用 IQR（四分位距）、3σ 法则、z-score、箱线图 四种方法找出异常值，并结合业务决定怎么处理，而不是一律删掉；
  4. 用 duplicated() / drop_duplicates() 正确处理重复行，说清 subset 参数的语义，知道处理顺序为什么会改变结果；
  5. 把格式混乱的列（带空格的文本、带单位的数字、中文日期）规整成能计算的类型；
  6. 说清什么时候必须做标准化（KNN、K-Means、SVM、PCA），什么时候不用做（决策树、随机森林）；
  7. 用 pd.cut / pd.qcut 分箱、用 get_dummies / map 编码类别，从现有列造出新特征；
  8. 把整条清洗链路写成一个可复用的函数，并和标准答案逐行对齐。

5.0 先搞清楚：数据预处理是什么

一句话：数据预处理就是把”人随手填出来的、给系统看的”原始数据，
整理成”机器能算、统计有意义”的规整数据。

为什么必须做？ 因为真实数据几乎从来不是干净的。它来自业务系统、Excel 手工登记、
爬虫抓取、多个部门各自导出再合并，于是必然出现下面这些东西：

你看到的 它为什么会这样 不管它会怎样
城市名前后多个空格 手工录入时手抖 “北京”和” 北京 “变成两个城市，分组统计直接算错
数量列里写着 3件 运营同事在 Excel 里打习惯了 整列变成文本，.mean() 报错
销售额空着 系统导出漏了、客户没付款 求和少算，均值被悄悄拉偏
销售额是负数 退货冲销 “最惨的订单”是 -9190 元，图表被拉垮
同一个订单出现两次 两个系统各导出一次 销售额被重复计算一倍
日期一会儿 2024-08-09、一会儿 2024年08月09日 不同人不同习惯 按月份统计时同一个月被拆成好几份
性别是空字符串 "" 用户没选，系统存了空串 它和”缺失”不是一回事，筛选逻辑会漏

5.2 缺失值处理

缺失值（missing value）：本来该有值、但表格里是空的那些格子。
在 pandas 里用 NaN（Not a Number，读作”三个字母 N-A-N”）表示，日期列的缺失用 NaT 表示。

为什么不能不管它？ 三个后果，都很实际：

  1. 算出来就是错的（或者算不出来）：df["销售额"].sum() 会跳过 NaN，所以求和会偏小；
    df["数量"].astype(int) 遇到 NaN 直接报错。
  2. 图会画歪：缺失行在画图时被悄悄丢掉，你看到的分布和真实分布不是一回事。
  3. 模型学不到东西：scikit-learn 的绝大部分模型不接受缺失值，会直接报错。

5.2.1 先分清：你到底在问什么

处理缺失值之前，必须先回答三个问题：

问题 为什么重要
缺多少？ 1% 还是 60%？ 缺 60% 的列基本没救，直接删列；缺 3% 可以放心填
为什么缺？ 是”随机漏了”还是”有原因地缺”？ 有原因的缺失本身可能就是信息（见 5.2.7）
这列要拿来干什么？ 要拿来算总和的列，不能随便填 0；只是分组标签的列，填个”未知”就够了

5.2.4 fillna()：常见填法有四种

填（imputation） 的思路是”用一个合理的值补上，让这一列能参与计算”。
四种填法的适用场景完全不同：

填法 代码 什么时候用 什么时候千万别用
常数 fillna(0) / fillna("未知") 缺失本身就代表”没有”，如”优惠券金额没填=没用券” 数值指标（销售额填 0 会让均值大幅偏低）
均值 fillna(s.mean()) 近似正态分布、缺失少的数值列 右偏严重的数据（会被极值带跑）
中位数 fillna(s.median()) 右偏数据（本章的数据就是） 有明显分组差异时（见 5.2.6）
众数 fillna(s.mode()[0]) 类别列（性别、支付方式） 数值列（众数毫无意义）

5.2.5 ffill / bfill / interpolate：前后向填充和插值

这三种是**”带着顺序”的填法**，只对有序列意义的数据才成立：

  • ffill()（forward fill，前向填充）：用上一个有值的格子填。
  • bfill()（backward fill，后向填充）：用下一个有值的格子填。
  • interpolate()（插值）：在两个已知值之间按线性关系算出中间的值。

5.3 异常值识别与处理

异常值（outlier）：和大多数观测值明显不在一个量级上的值。也叫”离群点”。

先记住一句话：异常值不一定是错误。

  • 可能是错误：年龄 200 岁、单价 0.0001 元、日期 1900 年；
  • 也可能是真实但极端：双十一的爆单、企业客户一次采购 5 万元；
  • 还可能是有业务含义的特殊值：本章的负销售额其实是退货。

不做处理的后果：均值被拉高、标准差被撑大、回归模型被一两笔大单带偏、
聚类时那些点会自成一类（见第 8 章的 K-Means）。

5.3.2 方法一：IQR 四分位距法（最常用）

思路：用数据的中间 50% 的”宽度”（IQR）作为正常范围，
超出 Q1 - 1.5×IQR 或 Q3 + 1.5×IQR 的就算异常。

  • Q1：25% 分位数（有 25% 的数据比它小）；
  • Q3：75% 分位数；
  • IQR = Q3 - Q1：中间一半数据的跨度，它不受极值影响（这正是它的优点）。

💡 IQR 什么时候最好用？ 数据近似对称、只是想揪出极个别离谱值的时候。

5.3.3 方法二和三：3σ 法则与 z-score

3σ 法则：如果数据近似正态分布，那么 99.7% 的值会落在
均值 ± 3×标准差 之内。超出的就算异常。

z-score（标准分数）：z = (x - 均值) / 标准差。
它表示”这个值离均值有几个标准差远”。|z| > 3 等价于 3σ 法则，
但 z-score 的写法更灵活（可以自己选 2.5 或 3.5 作阈值）。

5.4 重复值处理

重复值：同一笔业务在表里出现了多次。它比缺失值更危险，因为它不会报错，只会让数字变大。
销售额明明 159 万，因为重复行变成 165 万，你完全看不出来。

重复值的常见来源：

  • 多个系统各导出一次再合并（最常见）；
  • 手工登记时点了两次保存；
  • 数据同步任务失败重跑，把同一批数据写了两遍；
  • 导出时没加筛选条件，把历史数据也带进来了。

5.7 数值标准化与变换

标准化（scaling / normalization）：把不同量纲、不同范围的数值列，

先讲清楚一个新手最容易搞混的问题：到底什么时候需要标准化？

场景 需要标准化吗 为什么
KNN（K 近邻） ✅ 必须 它靠”距离”找最近的邻居。销售额范围 951083、年龄只有 1869，距离几乎完全由销售额决定，年龄等于没参与

SVM ✅ 必须 核函数基于内积/距离

线性回归 / 逻辑回归（带正则化） ⚠️ 建议 岭回归、Lasso 的惩罚项对所有系数一视同仁，不标准化会不公平；不加正则的普通最小二乘不影响预测结果，只影响系数的可读性
决策树 / 随机森林 / XGBoost ❌ 不需要 它们靠”某特征 > 某个阈值”来切分，阈值随尺度自动缩放，标准化不改变切分结构

拿到一列先 groupby(分组列)["目标列"].median() 看一眼组间差，
差得不多就别折腾了。

机器告诉你”这 3 个值很反常”，你要问的是”为什么反常”。
